# 数据库迁移约定

第一阶段创建 `users` 和 `auth_sessions` 两张基础表。第二阶段加入轻量迁移执行器和 `schema_migrations` 版本表。

已应用迁移：

- `0002_create_children`：新增 `children` 儿童档案表及必要索引，不修改或删除第一阶段数据。
- `0003_create_video_analyses`：新增与 `children.id` 关联的视频分析任务表，保存文件元数据、状态、进度和 JSON 结果；不修改或删除既有档案与账号数据。
- `0004_create_observation_records`：新增行为观察记录表，可选关联同一儿童的视频分析记录；删除视频时仅解除可选关联，删除儿童档案时级联删除其观察记录，不修改前三阶段数据。

迁移在应用启动和初始化脚本中自动执行；执行器先检查版本记录，因此可以安全重复运行。`create_all` 仍只负责全新数据库的管理员与会话基础表初始化，不用于修改已有业务表结构。

后续结构演进应继续使用可追踪迁移脚本或按需要引入 Alembic，并遵循：

1. 每次结构变更有独立版本号和升级说明。
2. 执行迁移前备份 `data/app.db`。
3. 不删除或重建已有管理员与会话数据，除非有明确迁移逻辑。
4. 迁移失败时终止启动并显示真实错误，不静默创建不一致结构。
